# ระบบใบสมัครงานออนไลน์ (Online Job Application System)

คู่มือการใช้งานและติดตั้งระบบใบสมัครงาน ที่แปลงมาจากแบบฟอร์มกระดาษ "APPLICATION FOR EMPLOYMENT / ใบสมัครงาน" ให้เป็นเว็บฟอร์มออนไลน์ พร้อมระบบเก็บข้อมูลบน **Firebase (Firestore + Authentication)** และหน้า **Admin Dashboard** สำหรับเจ้าหน้าที่

---

## 1. ไฟล์ในระบบ

| ไฟล์ | หน้าที่ |
|---|---|
| `job_application_system.html` | เว็บแอปทั้งระบบ (ฟอร์มสมัครงาน + หน้า Admin) รวมอยู่ในไฟล์เดียว |
| `firestore.rules` | กติกาความปลอดภัยของฐานข้อมูล Firestore ต้องนำไป Publish ใน Firebase Console |

ไฟล์ `job_application_system.html` เป็น static HTML — สามารถอัปโหลดขึ้น hosting ใดก็ได้ (Firebase Hosting, Netlify, GitHub Pages, เซิร์ฟเวอร์ของบริษัท ฯลฯ) โดยไม่ต้องมี backend เพิ่มเติม เพราะเชื่อมต่อ Firebase โดยตรงจากฝั่ง browser

---

## 2. ภาพรวมการทำงาน (Routing)

ไฟล์เดียวมี 2 หน้าจอ สลับกันด้วย URL hash:

| URL | หน้าที่แสดง |
|---|---|
| `job_application_system.html` (ไม่มี `#`) | หน้าฟอร์มสมัครงาน (ค่าเริ่มต้น) |
| `job_application_system.html#admin` | หน้า Admin (ล็อกอิน → Dashboard) |

มีลิงก์สลับหน้าให้ในตัวเว็บ ไม่ต้องพิมพ์ URL เอง:
- จากหน้าฟอร์ม: ลิงก์ **"สำหรับเจ้าหน้าที่ / Staff dashboard"** ด้านล่างฟอร์ม
- จากหน้า Admin: ลิงก์ **"← กลับไปหน้าสมัครงาน"** (หน้า login) และ **"← หน้าสมัครงาน / Form"** (มุมบนของ Dashboard)

---

## 3. หน้าฟอร์มสมัครงาน (Public Form)

หน้าตาและลำดับฟิลด์ตรงตามแบบฟอร์มกระดาษต้นฉบับ ครบทุกส่วน:

- ข้อมูลทั่วไป: ชื่อ, ตำแหน่งที่ต้องการ, เงินเดือน
- ข้อมูลส่วนตัว (Personal information): ที่อยู่ปัจจุบัน, เบอร์โทร/มือถือ/เพจเจอร์, อีเมล
- ลักษณะที่พักอาศัย (checkbox): อาศัยกับครอบครัว / บ้านตัวเอง / บ้านเช่า / หอพัก
- วันเดือนปีเกิด, อายุ, เชื้อชาติ, สัญชาติ, ศาสนา
- เลขบัตรประชาชน, วันหมดอายุบัตร
- ส่วนสูง, น้ำหนัก
- ภาวะทางทหาร (checkbox)
- สถานภาพสมรส (เลือกได้ 1 ตัวเลือกเท่านั้น เหมือน radio button)
- เพศ (เลือกได้ 1 ตัวเลือกเท่านั้น)

### ความสามารถของฟอร์ม

| ปุ่ม / ฟังก์ชัน | การทำงาน |
|---|---|
| **บันทึกข้อมูล / Save** | บันทึกข้อมูลทั้งหมดลง Firestore ทันที |
| **Autosave** | ระบบบันทึกข้อมูลอัตโนมัติเบื้องหลังทุกครั้งที่พิมพ์/ติ๊กช่อง (หน่วงเวลาเล็กน้อยเพื่อลดจำนวนการเขียนข้อมูล) |
| **ล้างข้อมูล / Clear** | ล้างข้อมูลในฟอร์ม และ **ลบ** ใบสมัครนั้นออกจาก Firebase ด้วย |
| **ใบสมัครใหม่ / New application** | เริ่มกรอกใบสมัครใหม่ (ใบสมัครเดิมยังถูกเก็บไว้ใน Firebase ไม่ถูกลบ) |
| จำข้อมูลของตัวเอง | เบราว์เซอร์แต่ละเครื่องจะจำ "document id" ของตัวเองไว้ (เก็บใน localStorage) เมื่อกลับมาเปิดฟอร์มใหม่ในเครื่อง/เบราว์เซอร์เดิม ข้อมูลเดิมจะโหลดกลับมาให้อัตโนมัติ |

> **หมายเหตุ:** ผู้กรอกฟอร์มไม่ต้องล็อกอิน สามารถกรอกและส่งได้ทันที

## 4. หน้า Admin Dashboard

เข้าถึงผ่าน `#admin` — ต้องล็อกอินก่อนจึงจะเห็นข้อมูล

### 4.1 หน้า Login
- ล็อกอินด้วย อีเมล + รหัสผ่าน ผ่าน Firebase Authentication
- ต้องสร้างบัญชีแอดมินไว้ล่วงหน้าใน Firebase Console (ดูขั้นตอนในหัวข้อ 6)

### 4.2 การ์ดสรุปข้อมูล (Summary Cards)
- จำนวนใบสมัครทั้งหมด
- จำนวนผู้สมัครชาย / หญิง
- อายุเฉลี่ยของผู้สมัครทั้งหมด

### 4.3 กราฟสรุป (แท่งเปรียบเทียบ)
- **ตำแหน่งที่มีผู้สมัครมากที่สุด** (Top 6 ตำแหน่ง)
- **สัดส่วนสถานภาพสมรส** (โสด / แต่งงาน / หม้าย / แยกกัน)

### 4.4 ตารางรายชื่อผู้สมัครทั้งหมด
แสดงคอลัมน์: ชื่อ, ตำแหน่ง, อายุ, เพศ, เบอร์มือถือ, อีเมล, วันที่ส่งใบสมัคร

| ความสามารถ | รายละเอียด |
|---|---|
| **ค้นหา** | พิมพ์ชื่อหรือตำแหน่งในช่องค้นหา ระบบกรองตารางแบบเรียลไทม์ |
| **ดูรายละเอียด** | คลิกที่ชื่อผู้สมัคร เพื่อเปิดหน้าต่างแสดงข้อมูลครบทุกฟิลด์ (ที่อยู่, บัตรประชาชน, ส่วนสูง/น้ำหนัก, ภาวะทางทหาร ฯลฯ) |
| **ลบใบสมัคร** | ปุ่ม "ลบ / Delete" ในแต่ละแถว (มีข้อความยืนยันก่อนลบ) |
| **รีเฟรช** | ดึงข้อมูลล่าสุดจาก Firestore อีกครั้ง |
| **ออกจากระบบ** | Sign out และกลับไปหน้า Login |

## 5. สถาปัตยกรรมและเทคโนโลยี

- **Frontend:** HTML + CSS + JavaScript (Vanilla JS, ES Modules) — ไม่มี framework, ไม่ต้อง build
- **Firebase SDK:** v10 (โหลดผ่าน CDN ของ Google โดยตรง ไม่ต้องติดตั้งอะไรเพิ่ม)
- **ฐานข้อมูล:** Cloud Firestore — collection ชื่อ `applications`
- **ระบบล็อกอินแอดมิน:** Firebase Authentication (วิธี Email/Password)
- **Firebase Project:** `mywebapp2569`

---

## 6. ขั้นตอนติดตั้ง (Setup Guide)

### ขั้นตอนที่ 1 — เปิดใช้ Firestore Database
Firebase Console → โปรเจกต์ `mywebapp2569` → เมนู **Firestore Database** → สร้างฐานข้อมูล (ถ้ายังไม่มี)

### ขั้นตอนที่ 2 — วาง Security Rules
Firestore Database → แท็บ **Rules** → คัดลอกเนื้อหาทั้งหมดจากไฟล์ `firestore.rules` วางแทนของเดิม → กด **Publish**

### ขั้นตอนที่ 3 — เปิดใช้ Authentication
เมนู **Authentication** → แท็บ **Sign-in method** → เปิดใช้ผู้ให้บริการ **Email/Password**

### ขั้นตอนที่ 4 — สร้างบัญชีแอดมิน
Authentication → แท็บ **Users** → **Add user** → กรอกอีเมล/รหัสผ่านที่จะใช้ล็อกอินเข้าหน้า Dashboard
(สร้างได้หลายบัญชี ทุกบัญชีที่สร้างในนี้ถือเป็นแอดมินเท่ากันหมด)

### ขั้นตอนที่ 5 — เผยแพร่เว็บไซต์
อัปโหลดไฟล์ `job_application_system.html` ขึ้น hosting ที่ต้องการ (เช่น Firebase Hosting, Netlify) แล้วแชร์ลิงก์ให้ผู้สมัครงานกรอกฟอร์มได้เลย

## 7. โครงสร้างข้อมูลใน Firestore

Collection: **`applications`** — แต่ละ document เก็บฟิลด์ต่อไปนี้ (ทุกฟิลด์เป็น string ยกเว้นที่ระบุ):

```
name, position, salary,
addr_no, addr_moo, addr_road, addr_subdistrict, addr_district, addr_province, addr_postcode,
tel, pager, mobile, email,
live_with_family, own_home, hired_house, hostel        (boolean)
dob, age, race, nationality, religion,
id_card_no, id_expiry,
height, weight,
mil_exempted, mil_served, mil_not_served                (boolean)
marital_single, marital_married, marital_widowed, marital_separated   (boolean)
sex_male, sex_female                                    (boolean)
createdAt, updatedAt                                     (timestamp, สร้างอัตโนมัติ)
```

## 8. สิทธิ์การเข้าถึงข้อมูล (Firestore Rules สรุป)

| การกระทำ | ใครทำได้ |
|---|---|
| สร้างใบสมัครใหม่ (`create`) | ทุกคน (ไม่ต้องล็อกอิน) |
| แก้ไข/บันทึกซ้ำ (`update`) | ทุกคนที่รู้ document id ของตัวเอง |
| ลบ (`delete`) | ทุกคนที่รู้ document id (รวมถึงแอดมิน) |
| ดึงข้อมูลทีละรายการ (`get`) | ทุกคนที่รู้ id |
| ดูรายชื่อผู้สมัครทั้งหมด (`list`) | **เฉพาะแอดมินที่ล็อกอินแล้วเท่านั้น** — เป็นสิ่งที่ทำให้ Dashboard ใช้งานได้ |

---

## 9. ข้อจำกัดและข้อควรระวัง

- ฟอร์มสาธารณะไม่มีระบบล็อกอิน จึงมีการตรวจสอบข้อมูลเบื้องต้นเท่านั้น (ต้องมีชื่อ, จำกัดขนาดข้อมูล) หากต้องการป้องกันสแปมเพิ่มเติม ควรพิจารณาเพิ่ม reCAPTCHA หรือ App Check
- ทุกบัญชีแอดมินมีสิทธิ์เท่ากันหมด (เห็น/ลบข้อมูลได้ทั้งหมด) ยังไม่มีการแบ่งระดับสิทธิ์ (role-based access)
- ตารางใน Dashboard โหลดข้อมูลทั้งหมดมาที่ฝั่ง browser แล้วค่อยกรอง เหมาะกับจำนวนผู้สมัครระดับหลักร้อยถึงพัน หากข้อมูลมีจำนวนมากมาก ควรพิจารณาทำ pagination หรือ query แบบแบ่งหน้า

## 10. แนวทางต่อยอดในอนาคต (ถ้าต้องการ)

- แบ่งระดับสิทธิ์แอดมิน (เช่น ดูอย่างเดียว vs ลบได้ด้วย) ด้วย Custom Claims
- ส่งอีเมลแจ้งเตือนเมื่อมีผู้สมัครใหม่ (Firebase Cloud Functions)
- ปุ่ม Export ข้อมูลเป็นไฟล์ Excel/CSV จากหน้า Dashboard
- เพิ่มระบบอัปโหลดรูปถ่ายผู้สมัคร (Firebase Storage)
